# 他の層と使い方が逆である。ask・declare・future は「当たったら記録する」肯定リストだが、

#
#   最終散文段落の末尾文が丁寧形（〜ます／〜ません）で終わり、
#   疑問・依頼で終わらず、かつ下記のどれにも当たらない → tier=negative として記録する。
#
# 着想（設計封筒 E-20990101000066-ee82 §2 案α）: 動作動詞は開放集合であり、
# `取りかかります` `行います` `お出しします` のように無限に言い換えられる。肯定リスト方式は
# その言い換えに追いつけない。一方で状態叙述・報告・待機・依頼の述語は閉じている見込みがある。
# この非対称が成り立てば、除外側を数え上げるほうが頑健になる。
#
# 実測（同封筒 §2・窓 2026-08-22T16:28Z〜2026-09-02T00:00Z・アンカーあり135本）:
# 肯定リスト38語は44本発火、本リスト45語は34本。否定のみが拾う8本は
# `お出しします` `コミットします` `回します` `入れます` `直します` など38語に無い動詞で、
# 肯定のみが拾う18本は大半が報告文・依頼文だった。

# 語の追加は、観測ログの実測読みに基づく場合に限り CC 裁量とする（同封筒 Task 1）。
